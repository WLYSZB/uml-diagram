# UML 建模规则（影响图语义与布局的实证结论）

以下规则来自 2026-10 实测验证。它们都不是工具缺陷，而是 DSL 语义陷阱：校验能过、图也能出，只是图错了。写图和改图前先对照本文件。

## 1. include / extend 方向

- `<<include>>`：箭头指向**被包含**的支撑用例。`取款 ..> 验证密码 : <<include>>` 表示取款必然包含验证密码。
- `<<extend>>`：箭头指向**被扩展**的基本用例。`短信通知 ..> 存款 : <<extend>>` 表示短信通知是存款的可选扩展。
- 记忆法：include "指向被用的"，extend "指向被扩的"。

## 2. actor 关联与 extend 的重复表达

actor 关联与 extend 并非天然重复，应先核对业务语义和 extend 方向。只有同一参与关系被重复表达时才删除冗余关联；不得仅为缩短连线而删除合法关系。extend 始终由扩展用例指向基本用例。

- 识别：用例图里出现特别长的弧线，提示可能存在同一参与关系被重复表达。
- 处理：先核对 extend 方向与业务语义，确认重复后再删冗余关联。

## 3. 组合 / 聚合的菱形端是"整体"

- 组合 `*--`：**菱形端是整体**。`图书 "1" *-- "0..*" 馆藏副本` = 图书由馆藏副本组成。
- 聚合 `o--`：同理，空心菱形端是整体。
- 写反了语义就倒置（"副本由图书组成"）。自查：读一遍"A 由 B 组成"是否符合业务。

## 4. 复合状态的外部迁移写在块外

复合状态块内引用外部状态名，外部状态会被**自动创建为它的子状态**，连线穿出边界，整张图乱掉。

- 错误：`state 借阅中 { 即将到期 --> 已逾期 }`
- 正确：`借阅中 --> 已逾期`（表示整个复合状态迁出）
- 自查：你以为的顶层状态如果画在了某个框里面，就是这条。

## 5. hide circle 与 stereotype 必须配套

theme.puml 的 `hide circle` 关掉了类名前的 C/I/E 彩色图标（标准 UML 不画），代价是接口和普通类外观完全一样。因此接口与枚举要用与模板一致的声明写法，别名可按需添加，关键是 stereotype 不可省：

```plantuml
interface Foo <<interface>>
enum Foo <<enumeration>>
```

- 只关图标不写 stereotype = 丢语义；两个开关配套使用。

## 6. 活动图：泳道数 × 嵌套层数 ≈ 布局质量

- 4 泳道 + 3 层嵌套判断：连线绕远、汇合菱形重叠、fork 粗线断成两截。
- 降到 2 泳道 + 无嵌套：主线一条直线。
- 活动图**不走 Graphviz**（PlantUML 内置排版器），降级或换引擎都救不了。唯一办法是拆图、减泳道、去嵌套。

## 7. 时序图：alt 标签与分页

- 分支一律用 `alt/else/end`，guard 写在分支标签上；时序图不画判断菱形。
- 同步消息实线实心箭头，返回消息虚线开放箭头、不编号、写返回值。
- 消息编号保持连续；拆页时编号接续（1–15 / 16–28），图注说明另一页位置。
- 完整版高度超过页高数倍时（实测 3456×7105），打印缩放后字不可读——按业务段落拆分，例如存款段、转账段各成一页。
- 当前包中的完整时序图只是"需要控制页高的长图"示例，不是分页结果。

## 8. 用例图坐标化：白名单与双档选择

坐标化渲染器（scripts/usecase_layout.py）只接受以下子集，白名单外的行会报错并给出行号原文：

- `@startuml`/`@enduml`、空行、单引号注释
- `!include`（仅限 theme 类纯样式文件；含模型定义即报错）
- `skinparam` / `title` / `hide` / `left to right` 等纯样式指令（忽略）
- `actor`、`usecase`（可带 `as` 别名）
- `rectangle|package` 系统边界（单个，不嵌套）
- 关系：`A -- B`（关联，不带标签）；`A ..> B : <<include>>` / `<<extend>>`（虚线必须带构造型）

双档选择：

- **自动版**（uml.sh png）：快，看结构；用例会横排、连线可能交叉。
- **坐标版**（usecase_layout.py --png）：业务用例纵向等距、支撑用例右侧汇聚、外部 actor 对齐，用于交付。
- 两版都保留；坐标版布局规则固定（主 actor 左侧居中、支撑用例 y=include 源质心、扩展用例在上方），不做任意手工排版。
